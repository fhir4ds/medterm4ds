# Recipe: Terminology Search — Live Demo

Try medterm4ds terminology operations right here, against a live public
endpoint: [terminology-demo](https://fhir4ds-terminology-demo-server.hf.space), a
Hugging Face Docker Space running the **native medterm4ds FHIR R4
terminology API** — the same app you can self-host, not a simplified
convenience layer.

## Native FHIR R4 operations

Every call the component above makes is a standard FHIR R4 operation with
a `Parameters` request body. The server's
[CapabilityStatement](https://fhir4ds-terminology-demo-server.hf.space/fhir/metadata)
lists everything it serves; the demo uses:

| Operation | FHIR request | What it does |
|---|---|---|
| Term search | `POST /fhir/CodeSystem/$search` | `query` + `searchMode` = `lexical` \| `semantic` \| `canonical` \| `hybrid`; returns a searchset `Bundle` of `CodeSystem` codings with match-grade extensions |
| Note extraction | `POST /fhir/CodeSystem/$extract` | `text` → a `Bundle` of concepts found by GLiNER + medspaCy NER, resolved to codes |
| Code detail | `POST /fhir/CodeSystem/$lookup` | `system` + `code` → `Parameters` with display, name and properties (incl. the UMLS CUI) |
| Code mapping | `POST /fhir/ConceptMap/$translate` | `system` + `code` + `targetSystem` → `Parameters` with equivalence-rated matches |
| Capabilities | `GET /fhir/metadata` | the `CapabilityStatement` |

The server also carries `$validate-code`, `$subsumes`, `$closure`,
`ValueSet/$expand`, `ConceptMap/$translate` by id, batch/transaction
`POST /fhir`, and resource-level reads — all unmodified from
`medterm4ds.create_fhir_app`.

### Example request and response ($search)

```json
POST /fhir/CodeSystem/$search
{
  "resourceType": "Parameters",
  "parameter": [
    {"name": "query", "valueString": "heart attack"},
    {"name": "searchMode", "valueCode": "hybrid"},
    {"name": "count", "valueInteger": 3}
  ]
}
```

```json
{
  "resourceType": "Bundle",
  "type": "searchset",
  "total": 3,
  "entry": [
    {
      "fullUrl": "CodeSystem/http://snomed.info/sct-22298006",
      "resource": {
        "system": "http://snomed.info/sct",
        "code": "22298006",
        "display": "Heart Attack"
      },
      "search": {
        "mode": "match",
        "score": 1.0,
        "extension": [
          {"url": "http://fhir4ds.org/fhir/StructureDefinition/match-grade",
           "valueCode": "certain"}
        ]
      }
    }
  ]
}
```

## The Space sleeps

The demo runs on free-tier hardware. After **48 h without traffic the
Space sleeps**, and the first request after sleep takes up to **~2 minutes**
to wake — about a minute of that is loading the terminology models
(SapBERT, FAISS, GLiNER; measured ~55 s on the live Space). The component
above polls the Space's health endpoint (which reports the model warm-up
separately from basic liveness), keeps the form disabled until queries
actually work, and shows that state explicitly ("Checking the terminology
server…", then "Starting up…").

## Browser calls the Space directly (and why)

This site is hosted on **GitHub Pages, which is static-only** — there is no
server-side component, so nothing can hide an API key or sign requests. The
demo above therefore calls the Space **directly, cross-origin**. The only
browser-side control is the Space's **origin allow-list**: calls from this
site's origin are accepted, calls from other websites' origins are refused,
and non-browser clients (curl, scripts) are allowed but rate-limited.

That allow-list is a **speed bump, not authentication** — the `Origin`
header is browser-supplied and trivially spoofed. Treat the Space as a
public demo endpoint, not an access-controlled API.

## Running your own

This demo is a Docker Space wrapping `medterm4ds.create_fhir_app`.
Everything is in the repo under `deploy/hf-spaces/terminology-demo/`
(Dockerfile, wrapper app, README with the deploy runbook and licence
notices). See [Docker deployment](../../interfaces/docker-deployment.md)
for self-hosting, or use the
[FHIR server](fhir-server.md) recipe for a FHIR-native surface.

## Rate limits & fair use

The public Space allows 30 requests/minute per IP. For anything heavier,
self-host — the data build is reproducible from your own UMLS download
(CPT excluded by design).
